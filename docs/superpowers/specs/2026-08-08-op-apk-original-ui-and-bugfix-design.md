# OP APK 原版 UI 对齐与兼容性修复设计

## 1. 目标

把当前项目 `android-app/` 的 APK 主页面、加载弹窗和成功弹窗调整为参考工程 `/Users/edking/Documents/网赚学习/op东鹏转发器/android-app/` 的蓝白原生界面风格，同时保留当前项目已经实现的两种业务模式：

- 9 位短 OP：通过 HTTPS 调用公开解析 API。
- 完整 OP：在本机离线校验、编码并完成授权回调或应用唤醒。

同时修复首轮检测确认的 Android 版本兼容性和覆盖安装问题，并生成可验证、可交付的 APK。

## 2. 非目标

- 不复制参考工程的 1.5 秒假加载延时。
- 不在界面、日志、弹窗、剪贴板或磁盘中展示或保存完整 OP、Token、唤醒 URL。
- 不改变短 OP API、服务端账号数据或 Web 管理后台。
- 不删除或覆盖 `apks/短位op.apk`、`.DS_Store` 或其他已有用户文件。
- 不在验证阶段覆盖连接设备上现有的原版 `com.tencent.mobileqq` 应用。

## 3. 方案选择

采用“移植视觉层、保留当前业务层”的方案：复用参考工程的布局结构、颜色、间距、图标和弹窗风格，但继续由当前 `MainActivity`、`ShortOpApiClient`、`OpWakeUrlBuilder` 和 `AgentActivity` 驱动真实业务。

未采用的方案：

- 整体复制参考工程 Activity：会带回假延时、明文 Token 片段，并丢失当前短 OP 联网解析行为。
- 改成 WebView 页面：难以保持原生弹窗、软键盘和多尺寸设备上的一致表现，且会扩大改动范围。

## 4. 主页面设计

主页面保持参考工程的纵向蓝白布局：

1. 顶部显示盾牌 OP Logo、“OP 上号器”和“安全授权，极速登录”。
2. 白色圆角提示卡显示当前请求模式：
   - 游戏授权调起时显示目标 AppID。
   - 独立打开时提示可输入 9 位短 OP 或完整 OP。
3. “粘贴 OP 数据”输入区保留大尺寸圆角输入框，提示文字明确两种格式。
4. 安全说明明确完整 OP 在本机处理、短 OP 仅通过 HTTPS 解析，输入不会保存。
5. 底部使用原版蓝色圆角盾牌按钮，文本为“点击授权登录”。
6. 底部帮助文案保留原版视觉层级，但不伪装成没有行为的可点击链接。

页面继续使用 `ScrollView`，保证小屏、软键盘打开和较大字体下仍可滚动访问按钮。所有用户可见文本进入字符串资源，避免 Java 和布局中散落硬编码。

## 5. 加载与成功弹窗

### 5.1 加载弹窗

- 用户提交合法非空输入后显示原版风格的不可重复提交加载弹窗。
- 9 位短 OP 的弹窗持续时间等于真实网络请求时间。
- 完整 OP 只执行本地校验和编码，不添加人为延时。
- 新 Intent 到达、Activity 销毁或请求失败时必须关闭弹窗并恢复按钮状态。
- 网络不可用、超时、限流、短码无效和完整 OP 格式错误继续显示明确错误，不进入成功弹窗。

### 5.2 成功弹窗

- 成功弹窗保留原版的勾选图标、标题、说明卡和蓝色确认按钮。
- 说明卡只显示“授权数据已安全处理”一类非敏感状态，不显示 Token 或 OP 片段。
- 游戏授权模式点击确认后返回 `op_data` 给 `AgentActivity`。
- 独立模式点击确认后打开服务端返回或本地生成的唤醒 URL。
- 找不到处理唤醒 URL 的应用时保留当前错误提示，Activity 不崩溃。

## 6. 状态与数据流

提交处理统一为以下状态：

1. `idle`：输入和按钮可用。
2. `loading`：保存本次请求编号和提交时的授权模式，禁用重复提交并显示加载弹窗。
3. `success`：仅在当前请求仍有效时关闭加载弹窗并显示成功弹窗。
4. `failure`：关闭加载弹窗、恢复页面状态并显示错误。

短 OP 继续使用请求编号门控，旧请求、取消请求和 Activity 销毁后的回调不能更新界面。完整 OP 和短 OP 最终都收敛为相同的“待返回 OP 数据或待打开唤醒 URL”结果，再由成功弹窗确认动作完成后续操作。

## 7. 已确认问题与修复范围

### 7.1 Android 7.0/7.1 运行风险

当前 `minSdk` 为 24，但 Lint 检出 20 个高版本 API 调用，包括 `java.util.Base64`、新式 `URLEncoder.encode`、`ByteArrayOutputStream.writeBytes`、`Instant.parse` 和新式 `ByteArrayOutputStream.toString`。实现应改用 API 24 可用的 Android/Java 接口，并用单元测试保持编码结果和响应解析契约不变，不通过提高 `minSdk` 掩盖问题。

### 7.2 无法覆盖原版安装

连接设备上的原版为 `versionCode=2599`、`versionName=9.0.0`，当前项目为 `versionCode=1`、`versionName=1.0.0`。新交付 APK 设置为 `versionCode=2600`、`versionName=9.0.1`，从而允许相同签名环境下正常升级，而不是要求降级安装或卸载原版。

### 7.3 Lint 警告

修复输入框自动填充声明、备份/数据提取规则和能够安全处理的图标资源警告。授权回调 Activity 的竖屏约束若属于协议兼容要求则保留，并在验证结果中明确列为已审查警告，不用 Lint baseline 隐藏现有错误。

### 7.4 本机构建配置

工程不提交包含绝对 SDK 路径的 `local.properties`。构建验证显式使用现有 `ANDROID_HOME`/`ANDROID_SDK_ROOT`，并在 Android README 中补充可复现命令。

## 8. 验证策略

### 8.1 自动验证

- 为 API 24 兼容实现补充回归测试，先证明当前高版本调用问题，再验证替代实现保持相同输出。
- 覆盖完整 OP 校验、二进制 plist/唤醒 URL 编码、短 OP 响应解析和失败分类。
- 覆盖请求门控，确认旧请求与销毁后的请求不会触发弹窗或回调。
- 运行 `testDebugUnitTest`、`lintDebug` 和 `assembleDebug`。
- Lint 必须为零错误；任何剩余警告逐项说明。
- 用 `aapt2` 和 `apksigner` 检查包名、版本号、最低版本、权限和签名。

### 8.2 设备验证

在临时工程副本中为调试构建追加独立 QA application ID，安装到已连接的小米 8，与原版并存，避免覆盖用户应用。设备验证包括：

- 主页面实际截图与原版截图对比。
- 小屏滚动、软键盘和输入框可用性。
- 空输入、错误完整 OP、无效短 OP和网络错误提示。
- 加载期间禁止重复提交。
- 成功弹窗不展示敏感数据。
- 游戏授权模式返回结果和独立模式唤醒路径。
- `logcat` 中无崩溃、ANR、完整 OP、Token 或唤醒 URL 泄露。

动态验证只使用虚构测试数据或无效短码，不使用真实账号凭证。

## 9. 交付物与验收标准

- `android-app/` 包含原版风格主页面和真实加载/成功弹窗逻辑。
- Android 7.0 兼容性错误和版本降级问题已修复。
- 单元测试、Lint 和 APK 构建通过。
- 已在连接设备上使用独立 QA 包完成实际渲染和基础交互检查。
- 最终 APK 复制为 `apks/tkacc-short-op-debug.apk`，同时保留已有 `apks/短位op.apk`。
- 最终报告区分源码验证、APK 静态检查和设备动态验证，不把未测试的真实第三方登录结果描述为已验证。
