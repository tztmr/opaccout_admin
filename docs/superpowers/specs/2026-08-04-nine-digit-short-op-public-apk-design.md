# 9 位短 OP、公开网页与 APK 双模式设计

## 1. 目标

在现有抖音账号管理系统中，把短 OP 直接绑定到账号主表，并提供公开网页、开放 API 和 Android APK 三个使用入口：

- 每条账号记录拥有一个服务端生成的唯一 9 位数字短 OP。
- 账号记录拥有项目字段，首版只内置抖音，默认 AppID 为 `1105602870`。
- 后台及现有管理 API 继续部署在 `https://tkacc.tztright.top`，根地址恢复进入后台登录页。
- 公开短 OP 页面和短 OP 开放 API 部署在 `https://op.tztright.qzz.io`，根地址直接显示输入页。
- `https://op.tztright.qzz.io/{code}` 提供带短码的分享入口。
- 网页与 APK 共用无需后台登录的短 OP 解析 API。
- APK 同时支持完整 OP 离线模式和 9 位短 OP 联网模式。
- 保留现有后台登录、账号管理、导入、导出和 OP 检测行为。

## 2. 非目标

- 首版不增加独立的短 OP 管理页面或独立短 OP 数据表。
- 首版不增加项目管理页面；只提供可扩展的项目目录并内置抖音。
- 不允许管理员手工指定、编辑或导入短 OP。
- 不改变完整 OP 卡密的加密存储方式。
- 不在公开网页上展示、复制或持久缓存完整 OP。

## 3. 方案选择

采用“账号主表直接绑定短 OP”的方案。一个账号、一份 OP 卡密、一个短码和一个项目共同组成同一业务记录，避免产生第二套列表、权限和生命周期。

未采用的方案：

- 独立短 OP 表：支持一条账号绑定多个短码，但会增加当前不需要的关联、启停和删除规则。
- 根据账号 ID 计算短码：不利于碰撞处理、吊销和安全控制。

## 4. 数据模型

### 4.1 账号字段

在现有 `Account` 模型增加：

- `shortOpCode: string`：恰好 9 位数字，全局唯一并建立唯一索引。
- `opProject: string`：稳定的项目键，默认值为 `douyin`。

首版项目目录：

| 项目键 | 显示名称 | AppID |
| --- | --- | --- |
| `douyin` | 抖音 | `1105602870` |

项目目录由共享领域模块统一提供。账号、公开 API、网页和 APK 均使用同一项目键和 AppID 映射，避免在不同入口重复维护数值。以后新增项目时扩展该目录和表单选项，不需要改变短码格式。

### 4.2 短码规则

- 短码是字符串，匹配 `^[1-9][0-9]{8}$`，范围为 `100000000` 至 `999999999`。
- 服务端使用密码学安全随机数生成；唯一索引冲突时重新生成。
- 新增账号和导入账号时自动生成，客户端请求中的短码字段一律忽略或拒绝。
- 编辑账号、替换 OP 卡密、修改项目或重新检测时保留原短码。
- 删除账号后短码立即失效；生成器不会主动复用旧码，但首版不为已删除账号保留永久墓碑。
- 现有账号通过幂等迁移补齐短码和默认项目；迁移可以安全重跑，并对并发唯一冲突重试。

## 5. 后台账号表

现有字段顺序保持不变，只在“OP卡密”后插入：

1. 短 OP
2. 项目

短 OP 单元格显示 9 位完整短码，提供：

- 复制短码。
- 复制完整分享链接 `https://op.tztright.qzz.io/{code}`。

项目单元格显示“抖音”。新增和编辑抽屉提供项目选择，首版只有抖音且默认选中；短码不出现在可编辑表单中。

搜索关键字应能匹配短 OP。CSV/XLSX 导出增加“短 OP”和“项目”列；导入模板可包含“项目”列，不填写时使用抖音。导入中的“短 OP”值不被采用，所有导入记录由服务端重新生成短码。

## 6. 公共网页与路由

后台域名路由：

- `GET https://tkacc.tztright.top/`：进入管理员登录页。
- `GET https://tkacc.tztright.top/login`：管理员登录。
- `GET https://tkacc.tztright.top/setup`：首次初始化管理员。
- `GET https://tkacc.tztright.top/accounts`：登录后的账号管理页。
- `GET https://tkacc.tztright.top/op`：重定向到 `https://op.tztright.qzz.io/`。
- `GET https://tkacc.tztright.top/op/:code`：保留短码并重定向到 `https://op.tztright.qzz.io/:code`。

公开页面域名路由：

- `GET https://op.tztright.qzz.io/`：渲染短 OP 输入页。
- `GET https://op.tztright.qzz.io/:code`：预填路径中的 9 位短码并允许提交。
- `/op` 与 `/op/:code` 可以作为兼容入口，但应重定向到上面的规范地址。
- 登录、初始化和账号管理页面不在公开 OP 域名提供。

React 路由根据受信任的主机名区分入口：后台域名的根路径进入登录页，公开 OP 域名的根路径在进入后台鉴权壳之前匹配短 OP 页面。Nginx 同时限制公开 OP 域名只提供短 OP 页面、静态资源和规范重定向，避免从该域名进入后台页面。

公开页面只接受 9 位数字，移动端使用数字键盘。解析成功后显示项目名称和“正在打开抖音”，随后使用返回的唤醒 URL；页面不把完整 OP 写入 DOM、剪贴板、本地存储或日志。

## 7. 开放 API

### 7.1 接口

生产规范地址属于公开 OP 域名：

```text
POST https://op.tztright.qzz.io/api/op/resolve
```

请求：

```json
{
  "code": "123456789"
}
```

成功响应：

```json
{
  "status": "success",
  "code": "123456789",
  "opData": "openid_demo|access_token_demo|pay_token_demo|pfkey_demo|1782303418",
  "project": {
    "key": "douyin",
    "name": "抖音",
    "appId": "1105602870"
  },
  "expiresAt": "2026-08-23T12:16:58.000Z",
  "wakeUrl": "tencent1105602870://qzapp/mqzone/0?..."
}
```

`opData` 是 APK 在游戏授权回调中必须使用的字段。短码本身因此等同于一份可取用的 OP 凭证，必须通过 HTTPS 传输并按敏感数据管理。

### 7.2 解析规则

服务端按顺序验证：

1. `code` 恰好为 9 位数字。
2. 账号存在且拥有该短码。
3. OP 到期时间晚于当前时间。
4. 账号状态不是 `op_invalid`。
5. 项目键存在且处于可用目录中。
6. 加密 OP 可以成功解密并生成唤醒 URL。

格式错误返回 `400`。不存在、过期、OP 失效、项目不可用或解密/编码失败统一返回 `404`：

```json
{
  "error": "短 OP 无效或已过期"
}
```

超过频率限制返回 `429`。服务端不在访问日志、错误日志或审计日志中记录 `opData`、解密后的 OP 或完整 `wakeUrl`。

### 7.3 开放与防护

- API 和页面无需管理员登录。
- 公共网页同源调用 `https://op.tztright.qzz.io/api/op/resolve`，不依赖跨域授权。
- APK 使用同一公开域名和接口，仍受格式校验和 IP 限流约束。
- 按客户端 IP 执行固定窗口限流，默认每分钟最多 30 次解析请求。
- Nginx 正确传递来源 IP，API 只信任受控反向代理链。
- 公开 OP 域名只向 API 容器代理精确路径 `/api/op/resolve`；不得代理登录、账号、导入、导出、设置或其他后台 API。
- 响应设置 `Cache-Control: no-store`，避免代理或浏览器缓存凭证。
- 不提供按短码查询账号资料、抖音号、归属人或备注的接口。

## 8. APK 双模式

当前项目新增 `android-app/`，复用参考项目的 Android 授权壳结构并修正为本项目的在线解析流程。

### 8.1 输入识别

- 输入匹配 `^[1-9][0-9]{8}$`：按 9 位短 OP 处理，联网请求开放 API。
- 其他非空输入：按完整 OP 处理，沿用本地离线授权流程。

### 8.2 运行行为

游戏授权流程调起 APK 时：

- 完整 OP 直接作为 `op_data` 返回。
- 9 位短 OP 解析成功后，使用响应中的 `opData` 作为 `op_data` 返回。

用户独立打开 APK 时：

- 完整 OP 在本地生成唤醒 URL。
- 9 位短 OP 解析成功后使用响应中的 `wakeUrl` 唤醒对应项目。

### 8.3 网络配置

- 默认 API 基址固定为 `https://op.tztright.qzz.io`。
- 调试构建允许通过 Gradle 属性覆盖 API 基址，正式构建默认值保持生产域名。
- Manifest 增加互联网权限。
- 正式构建拒绝明文 HTTP，网络请求设置连接与读取超时。
- 离线、超时、限流、无效短码分别给出明确提示；失败时不把空值返回给游戏。
- APK 不把解析响应写入磁盘、日志或剪贴板。

## 9. 组件边界

- `packages/shared`：短码格式、项目目录、DTO 和请求响应类型。
- API 账号模型与服务：短码生成、唯一冲突重试、现有数据补齐、项目默认值。
- API 公共解析服务：按短码查询、解密 OP、校验状态和到期时间、生成唤醒 URL。
- API 公共路由：输入校验、限流、`no-store` 响应和统一错误映射。
- Web 账号页：显示、搜索、复制、项目选择和导入导出字段。
- Web 公开页：输入短码、调用 API 和执行唤醒，不处理后台会话。
- Android：双模式输入、API 客户端、游戏回调和独立唤醒。
- 部署脚本：双域名 DNS 检查、Nginx 主机隔离、两张证书申请/续期、HTTPS 验证和部署状态输出。

这些边界保证短码生成与 OP 解密只发生在服务端，网页不需要知道账号管理细节，APK 也不复制后台业务逻辑。

## 10. 双域名部署与 SSL

现有 `deploy-opaccout-admin.sh` 只保存一个 `DOMAIN`、写一份 Nginx 配置并申请一张单域名证书，不能表达本次页面与 API 分域部署。脚本调整为：

- `ADMIN_DOMAIN`：默认 `tkacc.tztright.top`，承载后台和管理 API。
- `OP_PUBLIC_DOMAIN`：默认 `op.tztright.qzz.io`，承载公开短 OP 页面和精确的 `/api/op/resolve` 代理。
- 读取旧部署状态中的 `DOMAIN` 时将其迁移为 `ADMIN_DOMAIN`，避免现有安装失去后台域名配置。
- 配置 HTTPS 前分别检查两个域名的 DNS；提示中明确哪个域名未解析。
- 为两个域名写入独立 Nginx `server` 配置，不能让公开域名透传后台页面或全部 API。
- 后台域名的 `/op` 兼容路径使用 HTTPS 重定向到公开域名，并保留 9 位短码。
- 分别执行 Certbot 申请或更新证书，让两个证书可以独立续期和诊断；不把其中一个域名的失败误报为整体成功。
- 后台证书成功后把 `COOKIE_SECURE` 设为 `true` 并重建 API/Web 容器。
- 脚本状态页同时显示后台/API 地址、公开 OP 地址和两套证书状态。

部署完成后的规范地址：

| 用途 | 地址 |
| --- | --- |
| 后台入口 | `https://tkacc.tztright.top/login` |
| 开放 API | `https://op.tztright.qzz.io/api/op/resolve` |
| 公开短 OP 页面 | `https://op.tztright.qzz.io/` |
| 短码分享链接 | `https://op.tztright.qzz.io/{code}` |

## 11. 测试与验收

### 11.1 API 与数据

- 生成值始终为 9 位数字，唯一冲突会重试。
- 新增、批量导入和现有账号迁移都获得短码与默认抖音项目。
- 编辑账号和替换 OP 后短码保持不变。
- 关键词可搜索短码，导出列顺序正确，导入不能指定短码。
- 公共接口覆盖成功、格式错误、不存在、过期、`op_invalid`、项目不可用、解密失败和限流。
- 响应带 `Cache-Control: no-store`，日志中不出现完整 OP。

### 11.2 Web

- 未登录访问 `https://tkacc.tztright.top/` 进入后台登录页。
- `https://tkacc.tztright.top/op` 及其短码路径会保留短码并跳转到公开 OP 域名。
- 未登录访问 `https://op.tztright.qzz.io/` 和 `/:code` 不跳转 `/login`。
- 公开 OP 域名不能进入 `/login`、`/setup` 或 `/accounts`。
- 验证公开页面同源调用 `/api/op/resolve`，并确认公开域名无法访问其他 API。
- 手机与桌面尺寸下检查公开输入页和新增两列后的账号表实际渲染。
- 验证复制短码、复制分享链接、路径预填、成功唤醒和失败恢复按钮状态。

### 11.3 APK

- 完整 OP 在无网络环境保持原授权能力。
- 9 位短 OP 使用生产 API 或调试覆盖地址解析。
- 游戏调起模式正确返回 `op_data`，独立模式正确打开 `wakeUrl`。
- 网络不可用、超时、429 和无效短码不会导致崩溃或返回空授权结果。
- 执行离线 Gradle 构建，并把最终调试 APK 复制到项目 `apks/` 目录。

### 11.4 整体

- 运行共享包、API、Web 全量测试与类型检查。
- 运行 Android 单元测试和 `assembleDebug`。
- 构建 Docker Web/API 镜像并执行健康检查。
- 部署脚本分别检查 `tkacc.tztright.top` 与 `op.tztright.qzz.io` 的 DNS，写入独立 Nginx `server_name` 配置，并分别用 Certbot 申请或更新证书。
- 后台域名代理完整 Web/API；公开 OP 域名只代理公开页面、静态资源和精确的 `/api/op/resolve`，其他 `/api/` 路径直接拒绝。
- HTTPS 配置成功后验证后台登录入口、公开页面、短码路径、公开解析 API 和后台 API 隔离；脚本输出两个最终访问地址。
- 任一域名证书申请失败时保留已成功的配置并明确报告部分失败，不把双域名 SSL 宣称为全部完成。
- 只有完成浏览器视觉检查和 APK 产物构建后，才宣称网页与 APK 支持已完成。
