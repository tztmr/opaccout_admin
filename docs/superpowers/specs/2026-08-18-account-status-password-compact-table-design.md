# 账号状态区分、密码字段与紧凑表格设计

## 目标

完善抖音账号管理页的重新检测结果，使“封禁”和“违规”按照明确的处罚字段分别保存和显示；新增抖音账号登录密码字段；重新分配表格列宽，使账号列表在 1920×1080 桌面屏幕的默认页面宽度内无需拖动底部横向滚动条即可完成日常操作。

## 范围

本次修改包含：

- 抖音检测响应的状态解析与重新检测写回。
- 抖音账号登录密码的数据模型、加密存储、接口、表单、导入和导出。
- 账号列表新增“密码”列并直接显示密码内容。
- 账号列表列宽、长文本截断和操作区的紧凑布局。
- 对应的后端、共享类型和前端回归测试，以及桌面浏览器实际渲染验证。

本次不修改管理员登录密码逻辑，不新增账号状态种类，不删除现有表格功能，也不改变售卖状态与账号状态相互独立的业务规则。

## 账号状态检测

### 数据来源

首次检测和“重新检测”继续复用现有抖音检测客户端。已有 `sec_uid` 时优先请求 `profile/other`；该请求失败时继续使用当前按抖音号检测的回退路径。服务只提取状态判断所需字段，不记录完整第三方响应。

响应解析需要接受 `punish_remind_info` 中的 `ban_type`、`punish_title`、`is_punish`、`prompt_bar.content` 和 `punish_content.content`，并保留 `is_ban` 作为低优先级信号。

### 分类优先级

状态必须按照以下顺序判定，前面的命中后不再继续：

1. `ban_type === 1`，或 `punish_title` 为“账号已被封禁”：保存为 `banned`，界面显示“封禁”。
2. `ban_type === 2`，或标题/内容明确表示违规处罚、禁止关注，或 `is_punish === true`：保存为 `violation`，界面显示“违规”。
3. 没有处罚信息且 `is_ban === false`：保存为 `normal`，界面显示“正常”。
4. `is_ban === true` 但缺少可区分封禁与违规的明确字段，或响应信息不足：保存为 `unknown`，避免把封禁误写成违规。

这套规则同时应用于新增账号时的检测、单条重新检测和批量重新检测。重新检测成功后只刷新抖音派生字段；管理员维护的资料不被覆盖。

### 失败处理

网络失败、超时或无法解析的响应继续按现有服务策略处理，不把旧状态误改为“正常”。批量检测继续按每批最多 500 个 ID 执行，并保留已有的成功、失败和未确定项选择逻辑。

## 抖音账号登录密码

### 字段定义

新增可选字段 `accountPassword`，表示抖音账号登录密码，与管理员后台密码和 OP 卡密无关。历史记录迁移后该字段为空，界面显示 `—`。

密码支持：

- 新增账号时填写。
- 编辑账号时修改或清空。
- Excel、XLS 和 CSV 通过“密码”列导入。
- Excel 和 CSV 导出时包含“密码”列。
- 账号列表直接显示完整密码，不使用圆点、遮罩或二次点击查看。

编辑接口中不提交 `accountPassword` 表示保留原密码，提交空字符串表示清空密码，提交非空字符串表示替换密码。新增和导入时缺少该字段均表示空密码。

### 存储与接口

MongoDB 中不保存明文密码。服务端使用现有字段加密组件将非空密码加密为与 OP 卡密相同结构的密文；空密码不生成密文，以缺省字段表示。读取账号列表、单条详情和导出数据时，由已认证的服务端解密后返回。

由于用户明确要求表格不遮罩，已登录管理员可以从账号列表接口和页面直接看到密码明文。日志、审计记录和错误响应不得记录密码内容；审计只记录字段名发生变化。

搜索不索引密码，避免密码进入 `searchText` 或查询日志。

## 表格设计

### 列顺序

账号列表顺序调整为：

1. 选择框
2. 序号
3. 抖音号
4. 密码
5. `sec_uid`
6. 注册时间
7. OP 名称
8. OP 卡密
9. 短 OP
10. 项目
11. OP 到期时间
12. 归属人
13. 注册地区
14. 售卖状态
15. 账号状态
16. 备注
17. 操作

### 宽度策略

移除表格当前强制的 `min-width: 1720px`，改为固定布局和按业务优先级分配列宽。1920×1080、浏览器缩放 100%、侧边栏展开的默认页面作为桌面验收基线。

- 选择框、序号、项目和状态列使用紧凑固定宽度。
- 抖音号、密码、注册时间和归属人保留足够直接阅读的宽度。
- `sec_uid`、OP 名称、备注等长文本保持单行，超出时显示省略号，并通过 `title` 查看完整值。
- OP 卡密继续使用现有点击查看方式；新增的账号密码不遮罩。
- 短 OP 仍保留号码、复制和链接功能，但缩小内部间距。
- 操作列保留编辑、重新检测 OP、重新检测和删除，缩短按钮文案或使用现有图标与悬停说明，确保功能不丢失。

窄于桌面基线的窗口仍允许表格容器横向滚动，避免强行压缩至不可读；本次不把账号表格改为移动端卡片。

## 兼容性与迁移

现有 MongoDB 记录没有 `accountPassword` 时必须可以正常读取、编辑、检测和导出。模型默认值和 DTO 映射负责兼容旧数据，不要求一次性批量迁移数据库。

旧导入文件没有“密码”列时按空密码处理。新导出和新模板包含“密码”列，同时保留现有字段含义和导入别名。

## 测试与验收

### 自动化测试

- 状态解析：覆盖 `ban_type=1`、`ban_type=2`、封禁标题、违规标题/内容、正常响应，以及只有 `is_ban=true` 时返回未知。
- 账号服务：覆盖新增、编辑、读取、重新检测及历史无密码记录；验证数据库中不是明文密码。
- 导入导出：覆盖带密码、无密码和密码列顺序。
- 前端：覆盖密码列直接显示、历史空值显示 `—`、状态标签分别显示封禁与违规，以及现有重新检测交互不回退。
- 运行完整测试、类型检查、构建和 `git diff --check`。

### 浏览器验证

目标流程为：打开账号列表 → 查看密码列和封禁/违规状态 → 点击单条重新检测 → 列表刷新并显示正确状态。

桌面视口使用 1920×1080，检查：

- 页面身份和账号表格正常渲染。
- 首屏没有框架错误覆盖层或相关控制台错误。
- 表格无需拖动底部横向滚动条即可看到密码与操作列。
- 长文本截断后不挤压其他列，悬停信息存在。
- 密码直接显示，封禁与违规使用不同标签样式。
- 至少执行一次重新检测交互并核对刷新后的状态。

第三方抖音接口若在本地不可用，将把解析器和服务测试与真实第三方运行证明分开报告，不把模拟结果描述为线上接口已验证。
