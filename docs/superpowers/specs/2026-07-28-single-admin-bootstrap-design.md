# 一次性管理员初始化设计

日期：2026-07-28

## 目标

把当前由 Docker 环境变量提供管理员账号密码的登录方式，改为由 MongoDB 持久化唯一管理员。数据库中没有管理员时，后台默认显示管理员注册页；首个管理员注册成功后，注册页和注册入口立即消失，之后系统只允许登录，不允许再次注册或覆盖管理员。

本次迁移明确忽略旧的 `ADMIN_USERNAME`、`ADMIN_PASSWORD`。现有 MongoDB 中没有管理员记录，因此升级后的首次访问会进入管理员注册页。

## 范围

包含：

- MongoDB 唯一管理员凭据模型
- 首次初始化状态查询和注册接口
- 登录改为校验 MongoDB 管理员
- 首次注册成功后自动建立登录会话
- 注册页、登录页及其自动跳转
- Docker、环境变量示例和使用说明调整
- 后端、前端与 Docker 持久化验证

不包含：

- 多管理员、邀请、角色和权限系统
- 管理员自助改名、修改密码或找回密码
- 从旧环境变量自动迁移管理员
- 删除或重新开放管理员注册的页面功能

## 数据模型与密码安全

新增单管理员记录，使用固定主键 `primary`：

```text
_id              "primary"
username         string
passwordSalt     string
passwordHash     string
createdAt        date
updatedAt        date
```

固定主键同时承担数据库级唯一约束。即使两个客户端并发提交注册，MongoDB 也只能插入一个 `primary` 记录，后到的请求不会覆盖已创建的管理员。

密码不以明文保存。服务端使用 Node.js 内置 `scrypt` 和随机盐生成摘要，登录时重新计算摘要并使用恒定时间比较。接口、日志和审计记录都不返回或记录密码、盐、摘要。

用户名会去除首尾空白，长度为 1 至 100 个字符。密码长度为 12 至 4096 个字符。确认密码只用于前端交互，服务端仍独立校验实际密码规则。

## 后端接口

### 查询初始化状态

`GET /api/auth/setup`

这是一个无需登录的只读接口，只返回：

```json
{ "needsSetup": true }
```

或：

```json
{ "needsSetup": false }
```

它不返回管理员用户名或其他凭据信息。

### 注册首个管理员

`POST /api/auth/setup`

请求体：

```json
{
  "username": "admin",
  "password": "至少十二位密码"
}
```

处理顺序：

1. 校验输入格式。
2. 生成随机盐和密码摘要。
3. 尝试以固定主键 `primary` 插入管理员。
4. 插入成功后重新生成会话，写入管理员登录状态并返回认证结果。
5. 如果管理员已存在或并发请求抢先创建成功，返回 `409 ADMIN_ALREADY_EXISTS`，不更新原记录。

注册接口使用与登录接口同等级别的频率限制。注册过程中如果管理员已成功写入、但会话保存失败，管理员记录仍保留；页面刷新后会转到登录页，用户可以使用刚注册的账号正常登录。

### 登录

`POST /api/auth/login`

登录不再读取 `ADMIN_USERNAME`、`ADMIN_PASSWORD`，而是读取固定主键管理员记录并校验密码。

- 管理员不存在时返回 `409 SETUP_REQUIRED`，提示先完成管理员注册。
- 管理员存在但用户名或密码不正确时，统一返回 `401 AUTH_INVALID_CREDENTIALS`，不暴露具体错误字段。
- 登录成功后沿用现有安全会话、Cookie、退出和会话查询行为。

## 前端流程

新增独立路由 `/setup`：

- 未登录用户进入后台或 `/login` 时，前端先查询初始化状态。
- `needsSetup=true` 时自动进入 `/setup`，默认展示“注册管理员”表单。
- 表单包含用户名、密码、确认密码；两次密码不一致时在本地阻止提交。
- 注册成功后自动登录并跳转 `/accounts`。
- `needsSetup=false` 时，访问 `/setup` 会立即替换跳转到 `/login`，页面不再显示注册表单或注册入口。
- 登录页不提供“注册”按钮，因此首个管理员创建后只能登录。

若注册页面停留期间另一个客户端已完成注册，本客户端提交会收到 `ADMIN_ALREADY_EXISTS`，重新查询初始化状态并跳转登录页，不覆盖已存在管理员。

初始化状态加载期间显示统一加载状态；网络失败时显示可重试错误，不错误地展示注册或登录表单。

## 配置与部署

`ADMIN_USERNAME`、`ADMIN_PASSWORD` 从 API 必填配置、`.env.example` 和 `docker-compose.yml` 的 API 环境变量中移除。现有用户本地 `.env` 中即使仍保留这两个值，也会被应用忽略。

管理员记录保存在现有 MongoDB `mongo_data` 数据卷中，因此重新构建镜像、重启容器不会重新开放注册页。只有使用全新的空数据库才会再次进入首次初始化流程。

README 更新为：

1. 首次部署后打开后台。
2. 页面自动要求注册唯一管理员。
3. 注册完成后使用该账号登录。
4. 备份 MongoDB 数据卷；丢失管理员密码时不能依赖旧环境变量恢复。

## 错误与安全边界

- 服务端是注册是否开放的唯一判断者，不能只靠前端隐藏页面。
- 固定主键插入保证注册接口不可重复使用。
- 注册和登录均限制请求体大小、字段长度和请求频率。
- 错误响应不包含密码相关字段和数据库内部错误。
- 未认证用户仍不能访问账号、导入、导出、日志和设置接口。
- 本次不提供重置管理员功能，避免新增未经确认的凭据恢复入口。

## 测试与验收

后端自动化测试：

- 空数据库返回 `needsSetup=true`
- 首次注册成功、写入非明文摘要并自动建立会话
- 注册后返回 `needsSetup=false`
- 第二次注册和并发注册均返回冲突，原管理员不变
- 短密码和非法输入被拒绝
- 无管理员时登录提示先初始化
- 正确账号密码登录成功，错误账号或密码返回统一错误
- 退出和受保护路由行为保持不变

前端自动化测试：

- 无管理员时从登录流程自动进入注册页
- 密码确认不一致时不发送注册请求
- 注册成功后进入账号列表
- 已有管理员时 `/setup` 自动跳转登录页
- 并发注册冲突后转到登录页
- 初始化状态网络失败时显示错误和重试入口

最终验收：

- 在当前 Docker MongoDB 中确认无管理员时默认出现注册页
- 注册一个管理员后确认注册页和入口消失
- 退出后使用新管理员登录成功
- 重启 API、Web 和 MongoDB 容器后仍只能登录，不能重新注册
- 确认管理员记录中没有明文密码，API 与容器日志没有泄露凭据
- 运行完整 monorepo 测试、类型检查和生产构建
